Part 1 · Concepts

What are we even talking about?

An LLM — the brain 🧠

A model that predicts text. Incredibly capable — but it only knows what you feed it.

Claude Code — the agent 🤖

Lives in your terminal & repo. It can read files, run commands, and write code — with your permission.

Make the distinction explicit — Claude Code is NOT the AI. The LLM (Claude) is the AI: the brain that reasons. But a brain alone can't act and only knows what you feed it. Claude Code is the agent — the body / harness around the model that gives it hands: tools to read your files, run commands, edit code, in a loop, in your actual repo. The intelligence is the model; Claude Code is what lets it act and what feeds it context. Plant the caveat "the brain only knows what you show it" — it sets up context engineering on the next slide.

Prompt vs. context engineering

Prompt

What you ask.

Context

What the AI can see while answering.

Managing prompts & context is the real skill.

This is the spine of the whole act. Anyone can write a prompt. The craft is curating context: the right files, conventions, decisions, domain language. Tell them: we went DEEP on context — skills, conventions docs, delegating to subagents. Foreshadow: you'll see context strategy climb a ladder alongside trust.

First rung of BOTH ladders. You're in the driver's seat — plan, approve, repeat. Context lives in one window that you curate by hand. In the repo this is the manual workflow: grill → PRD → review → implement → validate → commit. Slow, but you learn the controls and you catch everything. Next slide: the concrete tools you use while in the loop.

First steps: plan mode & commands

📝 Plan mode — agree the approach before any code ⚡ Commands — small, repeatable everyday tasks

Walk before you run. That is how trust is built.

What living "in the loop" actually looks like. Plan mode = read-only, propose a plan, you approve. No surprises. Commands = your first taste of automating repeatable steps. You still approve everything — pure stage 1.

Extending the agentic layer

🧩 Skills — teach it your workflows 🔌 Plugins — bundle & share them 🔗 MCPs — connect outside tools & data 🤝 Subagents — delegate work to fresh context

Stop repeating yourself and start delegating context.

Skills = reusable, named procedures (in this repo: scaffold a backend slice, a frontend feature, an EF migration). Plugins = packaged skills. MCPs = bridges to databases, trackers, docs. Subagents = the big one for the context story: spin up a helper with its OWN clean context window, hand it a task, get back just the result. That keeps the main thread focused. This slide unlocks the next two rungs of the ladder.

Payoff slide — but keep it concrete. Don't say "two ladders". Just walk the diagram left to right out loud: "First I drive and hold all the context myself. Then I supervise while it uses subagents. Finally I review while it runs whole PRDs on its own." Same direction, every step — more trust, more delegated context. And you can only move right because you learned to set up context deliberately. Then hard pivot to the catch.
The catch

None of this works unless you understand the context —
- domain, architecture, technicalities...

If you don't, the AI quietly will take the lead —
and you get bad results without even noticing.

THE emotional punchline of Part 1. Slow down, let it land. The further you move out of the loop, the more you must already understand — the domain (conceptually) AND the codebase (technically). The danger isn't the AI failing loudly. It's the AI confidently doing the wrong thing while you nod along, because you couldn't tell the difference. You are the quality bar. The AI amplifies your judgment — it doesn't replace it. This is the bridge to Part 2: here's where I had to know my stuff.

How the AI actually built it

Idea → grill it → PRD → split into issues → agents build slices → reviewed PRs → merge

Every feature you just saw was built in one of the three stages

CONTEXT.md — the domain language ADRs — decisions on record conventions docs — the house style
Tie it all back. The reason I could go autonomous: I'd invested in context. CONTEXT.md teaches the AI our domain words. ADRs record the decisions so it doesn't re-litigate them. Conventions docs = our coding style, so output looks like ours. THIS is "understanding the context" made concrete — the punchline from Part 1, in practice.

Key takeaways

  • Direct the AI — don't just ask it for code.
  • Context is the craft — feed it well, delegate it deliberately.
  • Earn your way out of the loop — baby steps is the way to go.
Three things, said slowly. These are the whole talk in one slide. Land "trust follows understanding" as the last line — it ties both acts together.
